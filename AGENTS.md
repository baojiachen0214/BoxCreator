# Working on BoxCreator

For a packaging task, read `skills/boxcreator/SKILL.md`, then only the relevant documents it links. For a code change, inspect the affected module and run meaningful tests for its behavior.

The user supplies a dieline PDF and a short style brief, optionally references. The agent owns measurement, internal manifests, tool execution, diagnosis and delivery. Do not require the user to prepare engineering JSON. The deliverable is a complete vector net plus a Blender project/video, not a concept image or plan.

Preserve source dimensions and approved structure. Distinguish artwork, cut, crease, perforation, window, bleed and safe areas before modifying them. Keep artwork and all process lines separately editable. Use the same reviewed geometry and final artwork for PDF, SVG and Blender. Real windows must also be holes in the mesh.

Use AI illustration tools for requested illustrations; use deterministic geometry tools for placement and manufacturing paths. Choose vector-native design or trace approved raster artwork into actual paths. Do not claim that an SVG/PDF containing a raster is vector. Do not download large local models or assume a paid cloud account works; test the necessary capability on a small authorized sample.

Treat the playbook as decision guidance. Ask only about ambiguities that materially affect the outcome; continue independent work. Do not change frozen structure during an artwork-only revision. Keep a compact local checkpoint when long-running work or tool handoff is necessary.

Before claiming completion: visually review every face; measure final 1:1 outputs; toggle PDF layers; inspect vector contents; verify geometry and final texture match; watch the entire folding and full-orbit video; reopen the packed Blender project without external dependencies. Report physical-fit and printer checks honestly as pending when they have not happened.

Keep customer files, credentials, private paths, chat exports and generated media outside tracked source. Use the ignored working directories. Never put secrets in prompts, command arguments, examples or checkpoints. Before public release review the Git index, history and release assets. Publication requires the user's authorization for the repository/assets involved.
